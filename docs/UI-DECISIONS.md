# 界面视觉规范（UI Decisions）

这份文档记录 v1.3.0 界面重做的**判断依据**与**硬性规则**。
目的很具体：防止界面再退回「能用但看着廉价」的状态。

改动界面前请先读本文；新写的样式请逐条对照 §3 的自查表。

规则来源：本机 `fluent2-design-system` 技能（Fluent 2 官方实践）+ 本项目实测。
颜色/间距/字号**一律**走 `tokens.*`，不要写裸 hex 或裸 px。

---

## 1. 为什么要重做：六条根因

v1.3.0 首版交付后复盘，界面「丑」不是因为用错了组件，而是排版尺度与层次出了问题：

| # | 症状 | 归因 |
|---|---|---|
| 1 | 字太小、挤（大量 11–12.5px） | 缺统一字体阶，逐处手写小字号 |
| 2 | 层次扁平（画布/侧栏/表格几乎同色） | 未区分 surface，未用 elevation |
| 3 | 左栏大片空白 | 把枪名塞进 264px 窄栏，既不密也不清 |
| 4 | 工具栏拥挤、图标语义撞车 | 「批量导入」与「导入备份」共用同一个图标 |
| 5 | 每行重复噪音（每行都挂分类徽标、代码套 chip、3 个常驻图标） | 重复信息未下沉到容器层 |
| 6 | 行太密，扫 555 条吃力 | 未按 44px 扫读高度设计 |

**结论**：要改的是排版尺度 + 表面层次 + 信息架构，不是换框架。

---

## 2. 结构决策

### 2.1 三行外壳 + 两栏主区

```
┌─────────────────────────────────────────────┐
│ AppHeader   品牌·搜索·排序·视图·导入·备份·添加   │  auto   bg1 + 底线
├──────────────┬──────────────────────────────┤
│ NavTilePane  │  ContentPane                 │  1fr
│  分类选择器    │   SelectionBar（有选中才出现）  │
│  武器磁贴网格  │   DataGrid / Tree            │
├──────────────┴──────────────────────────────┤
│ StatusBar   统计 · 筛选 · 词库版本             │  auto   bg2 + 顶线
└─────────────────────────────────────────────┘
```

**为什么删掉原来的 NavDrawer 侧栏**：它把分类与枪名挤在 264px 竖栏里，中段大片空白，
而右侧表格又不够宽。改成「磁贴面板」后，分类变成一排紧凑按钮、枪名变成两列磁贴，
同等信息密度下更省高度，也让出宽度给真正要扫读的表格。

### 2.2 磁贴 = 一把枪

- 只保留扫读必需的两项：**枪名** + **配置条数**
- 分类用**左侧 3px 色条**表达，不用彩色徽标
- 点选 = 筛选该枪；再点 = 取消；**Ctrl/⌘ + 点击 = 多选**
  （这样保留了旧版「枪名多选」的能力，但不额外占用界面空间）

### 2.3 行操作收进溢出菜单

每行一个「⋯」菜单，而不是常驻三个图标。
555 行 × 3 图标 = 满屏图标；但完全隐藏又会让「操作」列在静止态显得是空的。
折中：每行一个弱化的溢出菜单，语义明确，噪声降到 1/3。

## 3. 硬性规则 + 自查表

### 3.1 字体阶

| 用途 | Token |
|---|---|
| 正文 / 表格单元格 | `fontSizeBase300`（14px） |
| 次级信息（时间、计数、提示） | `caption1`（12px） |
| 区块标题 | `body1Strong` / `Text weight="semibold" size={300..400}` |
| 改枪码 | `fontSizeBase300` + `fontFamilyMonospace` |

**禁止**出现小于 12px 的文本。全屏大量 11px 是廉价感的第一来源。

### 3.2 表面层次（三层，明度必须不同）

| 层 | Token | 用在哪 |
|---|---|---|
| 画布 | `colorNeutralBackground3` | 应用外壳底 |
| 面板 | `colorNeutralBackground2` | 磁贴导航、表头、状态栏 |
| 卡片 | `colorNeutralBackground1` | 内容卡片、表格、磁贴 |

- 浮起元素加阴影：卡片 `shadow2`，悬停 `shadow4`
- 分区用 1px `colorNeutralStroke2` 描边，不要靠加粗色块

### 3.3 间距与圆角

- 间距只用 `spacingVertical*` / `spacingHorizontal*`（4px 基准刻度）
- 圆角：卡片 `borderRadiusXLarge`(8px)，控件 `borderRadiusMedium`(4px)，**不要混用**
- 数据行最小高度 **44px**

### 3.4 降噪规则（最容易违反）

1. **同一信息不要在每一行重复**。分类已由磁贴/色条承载，就不要再给每行挂分类徽标。
2. **代码/ID 不做 chip 装饰**。等宽文本 + 悬停底纹即可，不要每行一个带框色块。
3. **重复语义的图标不要撞车**。同一屏里两个不同功能不要用同一个图标。
4. **行内操作默认弱化**（溢出菜单），不要常驻一排图标。

### 3.5 交互态

- rest → hover（更深）→ pressed（最深）
- 焦点态**加粗描边**，不换颜色；`:focus-visible` 必须保留（无障碍硬要求）
- 选中态用 `colorBrandBackground2` + `colorBrandStroke1`，不要只换文字颜色

### 3.6 中文

`tokens.fontFamilyBase` 默认栈**没有中文字形**。已在 `src/theme/theme.ts` 覆写为：

```
'Segoe UI Variable Text', 'Segoe UI', 'Microsoft YaHei UI', 'Microsoft YaHei', system-ui, ...
```

漏掉这步中文会回退到衬线体，观感立刻崩。新加主题时别忘了。

### 3.7 交付前自查表

- [ ] 没有小于 12px 的文本
- [ ] 画布 / 面板 / 卡片三层明度可区分
- [ ] 表格：行高 ≥44px，表头与数据行有底色+描边分层
- [ ] 没有「每行重复同一信息」（徽标、chip、图标）
- [ ] 同一屏没有两个功能共用同一个图标
- [ ] 圆角只用 8px（卡片）/ 4px（控件）两档
- [ ] 焦点环保留，图标按钮都有 `aria-label`
- [ ] 深浅两主题都看过（不要只看一个）

## 4. 踩过的坑（务必不要重犯）

### 4.1 不要给 `FluentProvider` 传 `className` 承载布局

它默认开启 `applyStylesToPortals`，会把 provider 的**整个 className**（含 griffel 哈希类）
复制到**每一个 portal 挂载节点**上；而 portal 节点自带
`position:absolute; top/left/right:0; z-index:1000000` + 不透明背景。

一旦 className 含 `height:100%`，**每个 Tooltip 的 portal 都会变成铺满窗口的遮罩**。
实测 22 个 Tooltip 直接把界面盖没，症状是「DOM 与命中测试全正常，但渲染只有一片底色」。

→ 布局请用**内联 `style`**（style 不随 `applyStylesToPortals` 传播）。

### 4.2 `NavCategoryItem` 的分类值在 `data.categoryValue`

`data.value` 恒为空串。用错字段表现为「分类永远展不开」。
（当前版本已不用 NavCategory，但若将来重新引入需注意。）

### 4.3 flex 子项默认 `min-width: auto` 会让 ellipsis 失效

长改枪码会溢出到相邻列（实测溢出 46px）。
容器链上每一层都要显式 `minWidth: 0`，否则 `text-overflow: ellipsis` 不生效。

### 4.4 `TreeItemLayout__main` 没有 `flex-grow`

Fluent 的 `__main` 只有 padding，`__aside` 带 `margin-left:auto`，
结果 main 按内容宽度收缩、aside 被推到最右，中间一大片空白。
从容器侧覆写：`"& .fui-TreeItemLayout__main": { flex: "1 1 auto", minWidth: 0 }`。

### 4.5 响应式断点必须按**窗口配置**定，不能凭感觉

`tauri.conf.json` 的窗口是 **1080×760**，`minWidth: 900`。

早期把「收为浮层」的断点设在 `1100px`，而 1080 < 1100 ——
**应用用它自己的默认尺寸打开时，磁贴面板就是收起的**，
用户一开始看到的是单栏布局。这个缺陷在浏览器里（我习惯用 1280 测）**完全看不到**，
只在真机 1080 截图里暴露。

同时 1080px 下顶栏还被撑成两行（88px），因为搜索框 320px 太宽。

**规则**：
- 断点必须对照 `tauri.conf.json` 的 `width`/`minWidth` 设定，不要用「看起来窄」当标准
- 默认尺寸（1080）下必须是「完整布局」：面板常驻、顶栏单行
- 900（最小）下允许顶栏两行，这是有意取舍，但**不能横向溢出**

**守住它的方式**：`.dsh/scripts/check-gca-sizes.mjs` 在 1080 / 900 / 1280
三个尺寸下自动断言「顶栏高度、面板是否常驻、是否横向溢出」。改布局后必跑。

### 4.6 **功能入口绝不能因为宽度被隐藏**

这是 4.5 的延伸，也是一次真实事故。

为了修「顶栏换行」，我把「词库管理 / 切换主题 / 批量导入」三个按钮
加了 `hideOnNarrow`（`max-width: 1080px` 时 `display:none`）。
而窗口宽度**正好是 1080px** —— 于是这三个功能在默认尺寸下**全部消失**。
其中「词库管理」是打开该面板的**唯一入口**，等于功能被彻底砍掉。

用户的反馈是「词库管理面板是不是没给入口」，实际是入口被 CSS 藏了。

**规则**：

1. 窄窗只允许**收起文字标签**，不允许隐藏按钮本身
   （保留图标 + `aria-label` + `Tooltip`，宽度从 ~120px 降到 32px）
2. 每个重要功能至少有**两个不同区域的入口**，避免单点被布局挤掉
3. 断点值不要等于窗口默认宽度（`1080` vs `1080` 会命中）

**词库管理现在的三处入口**：

| 位置 | 说明 |
|---|---|
| 侧栏底部「词库 vN · M 指纹」+「管理」 | **主入口**，符合直觉且不受顶栏宽度竞争影响 |
| 顶栏 `⟳` 图标按钮 | 常驻，窄窗只收文字 |
| 备份菜单 →「词库管理…」 | 兜底，菜单在任何尺寸下都可达 |

### 4.7 WebView2 的原生右键菜单必须处理

Tauri 2 默认不拦截 `contextmenu`，右键会弹出浏览器那套
「刷新 / 另存为 / 打印 / 检查」，在桌面应用里非常违和。

处理策略（`src/components/AppContextMenu.tsx`）：

- **可编辑区域**（`input` / `textarea` / `contenteditable`）→ **放行原生菜单**。
  输入法、拼写检查、粘贴历史依赖它，拦了会坏。
- **其它区域** → `preventDefault()`，弹应用自己的菜单：
  「复制」（有选中时）/「复制改枪码」（命中 `<code>` 时）/「全选」。

> 只 `preventDefault` 不提供替代菜单也是一种做法，但改枪码的核心操作就是复制，
> 右键复制是桌面应用的基本预期，所以做了轻量自定义菜单。

## 5. 验证方式

界面改动后跑这三步，缺一不可：

1. **E2E**：`.dsh/scripts/e2e-gca-ui.mjs`（CDP 驱动真实 DOM，111 项断言）
   - 覆盖磁贴选择、Ctrl 多选、分类切换、表格/分组视图、导入预览、删除确认、
     窄窗浮层导航、深浅主题
2. **尺寸矩阵**：`.dsh/scripts/check-gca-sizes.mjs`（1080 / 900 / 1280 三档）
   - 断言顶栏不换行、磁贴面板按断点正确常驻/收起、无横向溢出
3. **肉眼复核截图**：`gca-e2e-ui.mjs` 产出的截图，对照 §3.7 自查表逐项看

> **两条教训**（都真实踩过）：
> - 只跑 E2E 不看图 → 漏掉「操作列看起来是空的」这类纯视觉缺陷
> - 只在 1280 浏览器里测 → 漏掉「应用默认 1080 下顶栏两行、面板被收起」
>
> 所以：图要看，**尺寸也要专门测**，且必须包含 `tauri.conf.json` 里的真实默认值。
