# 本地改枪码

> ## ⚠️ 项目现状：原目标已废弃
>
> 本项目的初衷是做**自动化识别** —— 让程序拿到一串改枪码，就自动判断出它是哪把枪、
> 哪套配置。前后折腾了很久，最终确认这条路**走不通**：
> 改枪码里根本不编码枪械信息（详见下文[「一个必须知道的事实」](#一个必须知道的事实改枪码里没有枪械特征)）。
>
> 该目标现已放弃。项目转为**纯查表工具**：只认收录过的码，没收录的交给用户手动填。
> 这不是妥协，而是这个数据结构下唯一诚实的做法 —— 任何声称「能推断未知码属于哪把枪」的
> 方案，在没有官方接口之前都是不可靠的。
>
> 如果你也在琢磨同样的问题，可以先看下文的实测数据，省下这段弯路。

三角洲行动（Delta Force）玩家的**本地改枪码查表工具** —— 保存、查找、管理你的改枪码，完全本地运行，离线可用。

## 这个软件是干嘛的

三角洲行动里每把枪的改枪方案都对应一串**改枪码**（如 `6KFCC1K08QMG6NRUK6UQC`），可以在游戏内直接导入。但改枪码又多又长，群里/文档里翻来翻去很麻烦。

这个记事本帮你：

1. **粘贴即查表** —— 把改枪码粘进来，自动查出**枪名**和**配置名**（如 `RM277 + 20W青春版`、`MK47 + 75W满改红点`）。
   > 注意：这是**查表**不是推断。只有收录过的码才认得出，没收录的会显示「未知枪械」，需要你手动填一次（之后就会被记住）。
2. **批量导入（带预览）** —— 从在线文档/表格复制整块内容，先**解析预览**（可逐条勾选、查看识别依据、标记重复），确认后再入库
3. **自动学习** —— 手动填过的新枪/新配置，下次粘贴同指纹的码自动识别
4. **分类 + 枪名筛选** —— 按类别（步枪/冲锋枪/狙击枪/射手步枪/机枪/霰弹枪/手枪/弓）与**可搜索多选的枪名**组合筛选，支持按条数/名称/最近排序
5. **数据安全** —— 数据存在本地 JSON，支持一键**导出备份 / 导入恢复**，换电脑不丢

## 识别能力

| | v1.0.x | v1.1.0 | **v1.7.0** |
|---|---|---|---|
| 真实文档识别率 | 53% | 100% | **100%** |
| 指纹匹配 | 前 6 位（会冲突） | 前 10 位 | 前 10 位 |
| 规则库规模 | 硬编码 | 399 指纹 / 71 枪 | **2327 指纹 / 70 枪** |
| 枪名归属准确率 | — | 43.2%（**171 条错认**） | **100%（0 错认）** |
| 覆盖本机数据 | — | 307/553（漏 238） | **552/553** |
| 规则库更新 | 重新编译 | 手动替换文件 | **在线热更 + 学习表纠错** |
| 游戏模式 | 混收三个模式 | 仅烽火地带 | 仅烽火地带 |

> 「识别率 100%」指的是**收录过的码能认对**，不代表能认出任意新码 —— 后者不可能，见下节。

**关于三个模式**：三角洲的 `烽火地带` / `全面战场` / `黑潮爆破` 改枪码**兼容性未知**，
本工具**只收录烽火地带**。导入含其他模式的文档时，会按分区标题自动识别并跳过。

### 一个必须知道的事实：改枪码里没有「枪械特征」

v1.4.0 用 2255 条真实码做了结构分析（`docs/CODE-STRUCTURE.md`），结论是：

**改枪码不编码枪械信息。** 它只是一个唯一编号，同一把枪的不同配置、不同批次，
码的前缀毫无共性：

| 枪 | 样本数 | 码的公共前缀 |
|---|---|---|
| M7战斗步枪 | 93 | **1 位** |
| RM277突击步枪 | 93 | **1 位** |
| KC17突击步枪 | 63 | **1 位** |

121 把有 ≥3 条样本的枪里，**没有任何一把**前 10 位相同。
逐位置字符对枪名的区分力只有 **4.5%–36%**（接近随机）。

所以「前 10 位指纹」并不是特征，它标识的是**这一个具体配置**。
这意味着：

- 识别本质上是**查表**：见过的码能认对，没见过的只能显示「未知枪械」
- 第三方独立样本实测命中率 **19.1%**，这是查表机制的固有上限，不是 bug
- 提升覆盖面**只能靠多收录码**，不能靠推断规律

因此真正有用的三个机制是：**在线热更**（共享别人的收录）、
**学习表**（自己遇到的填一次就记住）、**导入预览**（批量喂新码）。

### v1.4.0 规则库重写说明

v1.1.0~v1.3.0 的规则库是从文档表格解析来的，存在**跨行继承错位**：
上一行的枪名被串到下一行的码上，导致同一把枪的码被认成别的枪。
实测你的 553 条数据里，**171 条认错枪（56.8%）**，典型如
`6JO080C04L` 被认成「野牛」实际是 SR25、`6JNV5PG08M` 被认成 MK47 实际是 SMG45。

v1.4.0 改为**三源合并**（优先级从高到低）：

| 优先级 | 来源 | 作用 |
|---|---|---|
| P0 | 你本机已保存的数据 | 权威，决定冲突时以谁为准 |
| P1 | `guns.anxu.cc` 公开方案 | 扩充覆盖（1702 条，指纹零冲突） |
| P2 | 旧规则库 | 仅保留未被推翻的条目 |

**规则库一律不写备注**：配置名由你自己填，不预填别人的文案
（早期版本曾把作者营销话术如「28w机密得吃巨浪！」当成配置名收进库）。

构建与验证脚本：

```bash
node scripts/fetch-anxu.mjs      # 抓取 anxu 线上样本（需联网）
node scripts/fetch-aitags.mjs    # 抓取 g.aitags.cn 主播样本（独立源，用于交叉验证）
node scripts/build-rules.mjs     # 三源合并生成 rules.json
node scripts/verify-rules.mjs    # 用你本机数据验证「错认=0」
node scripts/verify-external.mjs # 用第三方独立样本交叉验证（防循环论证）
node scripts/verify-merge.mjs    # 验证热更新不覆盖本地
```

### 交叉验证结果（第三方独立源）

用 `g.aitags.cn` 的 14 位主播、152 条样本（**完全没参与规则库构建**）检验：

| 指标 | 结果 |
|---|---|
| 命中且正确 | 29 |
| **命中但错认** | **0** |
| 未收录 | 123 |
| 精确率 | **100%** |
| 覆盖率 | 19.1%（查表机制的固有上限，见上节） |

> 早期交叉验证曾发现 2 条错认，都已处理：
> `MCX` 与 `MCX LT` 被当成两个条目（实为同一把枪，规范名为 `MCX LT`，`MCX` 作别名）；
> `6HHM76G03H` 本地标 MK47 但第三方标 M700（无法确认，已列入争议清单从库中排除）。

## 界面（v1.3.0 用 FluentUI 重做）

界面基于 **Microsoft FluentUI v9（Fluent 2 设计语言）**，不引入任何自绘组件或手写样式表。

整体是标准桌面应用外壳：**顶栏 / 主区 / 状态栏** 三行，主区再分**磁贴导航 + 内容**两栏。

- **顶栏**：品牌 · 搜索 · 排序菜单 · 表格/分组视图切换 · 批量导入 · 备份菜单 · 添加改枪码 · 主题与词库
- **磁贴导航（左栏）**：分类选择器（一排紧凑按钮）+ **武器磁贴网格**。
  一块磁贴 = 一把枪，标注配置条数；分类用左侧 3px 色条表达而非徽标。
  点磁贴即筛选该枪，**Ctrl/⌘ + 点击可多选**（沿用桌面端惯例，不额外占界面）。
- **内容区**：
  - **表格**：一行一条配置，列可拖拽调宽、支持多选（批量复制 / 批量删除）
  - **分组**：按枪折叠展开，适合逐把枪浏览
  - 行操作收进每行一个「⋯」菜单，而不是常驻三个图标
- **状态栏**：记录数 / 枪数 / 当前筛选 / 词库版本
- **添加与编辑合并为一个右侧抽屉（OverlayDrawer）**：粘贴后自动识别，显示置信度与识别依据
- **深色 / 浅色**一键切换（选择会记住），品牌色阶取自应用图标（蓝→紫）
- 窗口 <1100px 时磁贴导航收为浮层抽屉，由顶栏汉堡按钮唤起
- 骨架屏加载态、两态空状态（库为空 / 筛选无果）、搜索命中高亮、Fluent Toast 通知

> **排序只有一处真源**（顶栏排序菜单），表格表头不参与排序，避免两个入口互相覆盖。
>
> **视觉规范**见 `docs/UI-DECISIONS.md`：字体阶、表面层次、行高、降噪规则都写在那里，
> 改动界面前请先读，避免回退到「能用但廉价」的状态。

## 使用说明

### 添加单条
1. 点右上角「添加」→ 右侧抽屉滑出
2. 粘贴改枪码 → 自动识别枪名 + 配置名（可手动修改）
3. 点「保存」

### 批量导入（带预览）
1. 点「批量导入」
2. 从在线文档/表格复制整段内容粘贴进来
3. 点「解析并预览」→ **先看预览**（可逐条勾选、查看识别依据、标记重复）
4. 确认无误点「确认导入（N）」

支持的格式示例：
```
RM277 20W青春版 6KFCC1K08QMG6NRUK6UQC
MK47突击步枪-烽火地带-6HN54R808PBNCS3LFEE0A
```

### 筛选与查找
- **类别**：左侧边栏点选（步枪 / 冲锋枪 / 狙击枪 / 射手步枪 / 机枪 / 霰弹枪 / 手枪 / 弓 / 其他）
- **枪名**：工具栏「枪名」按钮 → 可搜索的**多选**浮层
- **搜索**：枪名/代码/备注，**归一化匹配**（搜 `ak12` 也能命中 `AK-12`），命中片段高亮
- **排序**：按条数 / 名称 / 最近
- 以上可**自由组合**，筛选状态会记住

### 备份
- 「导出 JSON 备份」→ 选保存位置
- 「导入 JSON 备份」→ 选之前导出的文件，自动合并（按代码去重）

### 两个务必注意的 FluentUI 坑（都已在代码注释中标注）

1. **不要给 `FluentProvider` 传 `className` 承载布局。**
   它的 `applyStylesToPortals`（默认开）会把整个 className 复制到每个 portal 挂载节点上；
   而 portal 节点自带 `position:absolute; inset-inline:0; z-index:1000000` 且有不透明背景。
   一旦 className 里有 `height:100%`，每个 Tooltip 的 portal 都会变成铺满窗口的遮罩
   —— 实测 22 个 Tooltip 直接把界面盖没。布局请用 `style`。
2. **`NavCategoryItem` 的展开回调里，分类值在 `data.categoryValue`**，
   `data.value` 恒为空串。用错字段表现为「分类永远展不开」。

## 隐私

- **你的改枪码数据 100% 存本地**，不上传、不备份到云端
- **无任何广告、统计、遥测**
- **默认不联网**。唯一的联网动作是「词库管理 → 检查更新」，**只有你手动点击才会发请求**，
  且只拉取公开的规则库 JSON（GitHub raw / jsDelivr），不发送任何你的数据
- 不点「检查更新」，全程可完全离线使用

## 词库热更新与纠错（v1.4.0）

顶栏的 ⟳ 按钮打开「词库管理」，含两个独立能力：

### 在线更新

- 来源按顺序尝试：**GitHub raw → jsDelivr**（前者缓存 5 分钟更新及时，后者国内可达性好）
- 采用**本地优先**策略：远程只补充你本地未收录的指纹，**绝不覆盖已有条目**
  - 原因：本地数据是你自己确认过的；远程库也可能有解析错误
  - 实测教训：v5 规则库有 56.8% 的枪名归属错误，若让远程覆盖本地，用户数据会被污染
- 「重置为随包词库」可清除合并结果，回到安装包自带的那份

### 学习表纠错

**这是本次新增的重要能力**：以前输错枪名后没有任何办法纠正。

- 学习表的优先级**高于**词库 —— 保存/编辑时填的枪名会被记住，之后同指纹的码都按它识别
- 若某条学错了，在列表里删掉对应指纹即可恢复按词库识别
- 会标出**与词库冲突**的条目（黄色警告），方便定位问题
- 「全部清空」一键重置，**不会删除你保存的改枪码记录**

> 为什么需要它：学习表只增不减时，一条输错的记录会让某个指纹**永久**认错，
> 而用户完全无从下手。这是实际反馈过的痛点。

## 项目沿革

这个项目的目标漂移过三次，写下来供后来者参考：

| 阶段 | 原目标 | 实际结果 |
|---|---|---|
| v1.0 | 硬编码规则识别枪名 | 真实文档识别率 53% |
| v1.1–v1.3 | 用「前 10 位指纹」查表 | 文档识别率上去了，但**枪名归属 56.8% 错**（解析时跨行错位） |
| **v1.4–v1.7** | **原本想做自动推断，确认不可行后放弃** | 改为**纯查表**：三源合并重写规则库（错认 171 → 0）、在线热更、学习表纠错、本地/线上分层存储 |

**放弃自动推断的原因**（完整分析见 [`docs/CODE-STRUCTURE.md`](docs/CODE-STRUCTURE.md)）：

- 用 2255 条真实码做过结构分析：同一把枪的码，公共前缀平均只有 **1.1 位**
- 121 把有足够样本的枪里，**没有任何一把**前 10 位相同
- 逐位置字符对枪名的区分力 **4.5%–36%**，接近随机
- 结论：改枪码是**唯一编号**，不编码枪械信息。查表是唯一可靠路径

所以现在这个工具的定位很明确：**它是个查表器，不是识别器**。
价值在于把「收录」这件事做好 —— 通过在线热更共享别人的收录、通过学习表记住你遇到的码。
